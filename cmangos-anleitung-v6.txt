================================================================================
  CMaNGOS — Vollständige Docker Anleitung (Playerbots + AH-Bot + AI Chat)
  Gültig für: Classic 1.12  |  TBC 2.4.3
  Version 6 — Vollständig praxisgetestet für Classic UND TBC
================================================================================


EXPANSION-REFERENZ
────────────────────────────────────────
Diese Anleitung gilt für beide Expansions. Überall wo Werte sich unterscheiden
wird eine Tabelle gezeigt:

  | Einstellung        | Classic 1.12          | TBC 2.4.3             |
  |--------------------|------------------------|------------------------|
  | Arbeitsverzeichnis | cmangos-classic        | cmangos-tbc            |
  | Git Repo (Core)    | mangos-classic         | mangos-tbc             |
  | Git Repo (DB)      | classic-db             | tbc-db                 |
  | Docker Image Tag   | cmangos-classic        | cmangos-tbc            |
  | DB World           | classicmangos          | tbcmangos              |
  | DB Characters      | classiccharacters      | tbccharacters          |
  | DB Logs            | classiclogs            | tbclogs                |
  | DB Realm           | classicrealmd          | tbcrealmd              |
  | Docker Netzwerk    | cmangos-classic_...    | cmangos-tbc_...        |
  | WoW Client         | 1.12.x                 | 2.4.3                  |

In den Befehlen dieser Anleitung wird "classic" als Platzhalter verwendet.
Für TBC einfach alle Vorkommen von "classic" durch "tbc" ersetzen.


CONTAINER IN DIESEM SETUP
────────────────────────────────────────
  cmangos-db        MariaDB Datenbank
  cmangos-mangosd   WoW Weltserver  ──────────────┐
  cmangos-realmd    Authentifizierung             │ redet über mangos-net
  koboldcpp         KI-Sprachmodell  ─────────────┘

1. Playerbots (ike3/celguar)
   200 Random Bot Accounts mit ~1800 Charakteren, erstellt beim ersten Start.
   Konfiguration: aiplayerbot.conf

2. AH-Bot — Befüllt das Auktionshaus automatisch.
   Konfiguration: ahbot.conf

3. KoboldCPP AI Chat — Lokales KI-Modell für echte Bot-Antworten.
   Konfiguration: AiPlayerbot.LLMApiEndpoint in aiplayerbot.conf


VORAUSSETZUNGEN
────────────────────────────────────────
- Docker + Docker Buildx:
    sudo pacman -S docker-buildx
- User zur Docker-Gruppe hinzufügen (einmalig):
    sudo usermod -aG docker $USER && newgrp docker
- WoW Client passend zur Expansion vorhanden

WICHTIGE HINWEISE:
  - Maps/vmaps von anderen Emulatoren sind NICHT kompatibel — immer selbst
    extrahieren!
  - Docker schreibt Dateien als root — nach jeder Extraktion chown ausfuehren
  - aiplayerbot.conf wird unter /opt/etc/ gesucht (NICHT /opt/mangos/etc/)
    — SYSCONFDIR = "../etc" relativ zur Binary in /opt/mangos/bin/
    Das ist in Dockerfile und docker-compose.yml dieser Anleitung korrekt

================================================================================
  SCHRITT 2 — Dockerfile anlegen
================================================================================

nano Dockerfile

Inhalt (gilt fuer beide Expansions — nur git clone URL aendern!):
───────
# Stage 1: Build
FROM archlinux:latest AS builder

RUN pacman -Syu --noconfirm \
    base-devel git cmake mariadb mariadb-libs boost boost-libs

WORKDIR /build

# Classic: mangos-classic  |  TBC: mangos-tbc
RUN git clone https://github.com/cmangos/mangos-classic.git mangos

RUN mkdir build && cd build && \
    cmake ../mangos \
        -DCMAKE_INSTALL_PREFIX=/opt/mangos \
        -DBUILD_EXTRACTORS=ON \
        -DBUILD_PLAYERBOTS=ON \
        -DBUILD_AHBOT=ON \
        -DPCH=1 \
        -DDEBUG=0 && \
    make -j$(nproc) && \
    make install

# Configs vorbereiten
# ahbot.conf aus Quellcode (nicht .dist) um "Too few values" Fehler zu vermeiden
RUN cd /opt/mangos/etc && \
    cp mangosd.conf.dist mangosd.conf && \
    cp realmd.conf.dist realmd.conf && \
    cp anticheat.conf.dist anticheat.conf && \
    cp /build/mangos/src/game/AuctionHouseBot/ahbot.conf.dist.in ahbot.conf

# aiplayerbot.conf nach /opt/etc/ kopieren (SYSCONFDIR-Pfad der Binary!)
RUN mkdir -p /opt/etc && \
    cp /opt/mangos/etc/aiplayerbot.conf.dist /opt/etc/aiplayerbot.conf

# Stage 2: Runtime
FROM archlinux:latest AS runtime

RUN pacman -Syu --noconfirm \
    mariadb-libs mariadb-clients boost-libs openssl

COPY --from=builder /opt/mangos /opt/mangos
COPY --from=builder /opt/etc /opt/etc

WORKDIR /opt/mangos

Fuer TBC: Zeile "RUN git clone" aendern auf:
  RUN git clone https://github.com/cmangos/mangos-tbc.git mangos

================================================================================
  SCHRITT 6 — Mapdaten extrahieren
================================================================================

# Classic:
docker run --rm -it \
    -v /programmieren/WoW/cmangos-classic/wow-client:/wow \
    cmangos-classic \
    bash -c "
        cp /opt/mangos/bin/tools/* /wow/ && \
        cd /wow && \
        sed -i 's/\r//' ExtractResources.sh && \
        bash ./ExtractResources.sh
    "

# TBC (cmangos-tbc statt cmangos-classic):
docker run --rm -it \
    -v /programmieren/WoW/cmangos-tbc/wow-client:/wow \
    cmangos-tbc \
    bash -c "
        cp /opt/mangos/bin/tools/* /wow/ && \
        cd /wow && \
        sed -i 's/\r//' ExtractResources.sh && \
        bash ./ExtractResources.sh
    "

Fragen im Skript — empfohlene Antworten:
  Should all dataz be extracted?          -> n
  Should dbc and maps be extracted?       -> y
  Should vmaps be extracted?              -> y
  Should mmaps be extracted?              -> n   (Stunden! Spaeter nachholen)
  Only reextract offmesh tiles?           -> n   (WICHTIG: n, nicht y!)
  High-resolution maps?                   -> n
  High-resolution vmaps?                  -> n

--- FALLS "Your output directory seems to be polluted" ---
  rm -rf wow-client/Buildings
  rm -rf wow-client/vmaps

--- NACH DER EXTRAKTION ---
# Berechtigungen korrigieren (Docker schreibt als root!)
sudo chown -R $USER:$USER wow-client/

# Daten verschieben (Pfad je nach Expansion anpassen)
mv wow-client/maps  data/
mv wow-client/dbc   data/
mv wow-client/vmaps data/

sudo chown -R $USER:$USER data/

--- MMAPS NACHTRAEGLICH ---
# Classic:
docker run --rm -it \
    -v /programmieren/WoW/cmangos-classic/wow-client:/wow \
    -v /programmieren/WoW/cmangos-classic/data/maps:/wow/maps \
    -v /programmieren/WoW/cmangos-classic/data/vmaps:/wow/vmaps \
    -v /programmieren/WoW/cmangos-classic/data:/data \
    cmangos-classic \
    bash -c "
        mkdir -p /wow/mmaps && cd /wow && \
        ./MoveMapGen --offMeshInput offmesh.txt 0 --threads $(nproc) && \
        ./MoveMapGen --offMeshInput offmesh.txt 1 --threads $(nproc) && \
        cp mmaps/* /data/mmaps/
    "
sudo chown -R $USER:$USER data/mmaps/

nano docker-compose.yml

# Classic-Version (fuer TBC: alle "classic" durch "tbc" ersetzen,
#                  Ports anpassen wenn beide gleichzeitig laufen sollen):
───────
services:

  db:
    image: mariadb:10.11
    container_name: cmangos-db
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_USER: mangos
      MYSQL_PASSWORD: mangos
    volumes:
      - db_data:/var/lib/mysql
      - ./sql-init:/docker-entrypoint-initdb.d
    networks:
      - mangos-net
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 10s
      timeout: 5s
      retries: 10

  mangosd:
    image: cmangos-classic        # TBC: cmangos-tbc
    container_name: cmangos-mangosd
    command: /opt/mangos/bin/mangosd -c /opt/mangos/etc/mangosd.conf -a /opt/mangos/etc/ahbot.conf
    volumes:
      - ./data/maps:/opt/mangos/maps
      - ./data/dbc:/opt/mangos/dbc
      - ./data/vmaps:/opt/mangos/vmaps
      - ./data/mmaps:/opt/mangos/mmaps
      - ./config/mangosd.conf:/opt/mangos/etc/mangosd.conf
      - ./config/ahbot.conf:/opt/mangos/etc/ahbot.conf
      # aiplayerbot.conf MUSS nach /opt/etc/ (nicht /opt/mangos/etc/!)
      - ./config/aiplayerbot.conf:/opt/etc/aiplayerbot.conf
    ports:
      - "8085:8085"   # TBC gleichzeitig mit Classic: 8086:8085
    depends_on:
      db:
        condition: service_healthy
    networks:
      - mangos-net
    restart: unless-stopped
    stdin_open: true
    tty: true

  realmd:
    image: cmangos-classic        # TBC: cmangos-tbc
    container_name: cmangos-realmd
    command: /opt/mangos/bin/realmd -c /opt/mangos/etc/realmd.conf
    volumes:
      - ./config/realmd.conf:/opt/mangos/etc/realmd.conf
    ports:
      - "3724:3724"   # TBC gleichzeitig mit Classic: 3725:3724
    depends_on:
      db:
        condition: service_healthy
    networks:
      - mangos-net
    restart: unless-stopped

  koboldcpp:
    image: koboldai/koboldcpp:latest
    container_name: koboldcpp
    environment:
      KCPP_DONT_TUNNEL: "true"
      KCPP_DONT_UPDATE: "true"
      KCPP_ARGS: "--model /models/Llama-3.2-1B-Instruct-Uncensored.Q8_0.gguf --port 5001 --host 0.0.0.0 --threads 4 --nommap"
    volumes:
      - ./ai-models:/models
      - koboldcpp_bin:/workspace
    ports:
      - "5001:5001"   # TBC gleichzeitig mit Classic: 5002:5001
    networks:
      - mangos-net
    restart: unless-stopped

networks:
  mangos-net:

volumes:
  db_data:
  koboldcpp_bin:

Hinweis: koboldcpp NUR per environment/KCPP_ARGS konfigurieren — kein

================================================================================
  SCHRITT 12 — Datenbank-Updates einspielen (PFLICHT!)
================================================================================

Nach dem InstallFullDB erscheint ggf.:
  "Warning: These DBs need core update: 'realmd' 'characters' 'logs'
   You can use option 3 to apply latest core update"

FALLS InstallFullDB Option 3 mit Fehler abbricht ("10#: invalid integer
constant" — bekannter Bash-Bug), die Updates manuell einspielen:

# Classic:
docker run --rm -it \
    --network cmangos-classic_mangos-net \
    -v /programmieren/WoW/cmangos-classic/mangos-src:/mangos \
    cmangos-classic \
    bash -c "
        echo '--- characters base schema ---'
        mariadb --skip-ssl -hdb -umangos -pmangos classiccharacters \
            < /mangos/sql/base/characters.sql
        echo '--- characters updates ---'
        find /mangos/sql/updates/characters -name '*.sql' | sort | \
            while read f; do
                mariadb --skip-ssl -hdb -umangos -pmangos classiccharacters \
                    < \$f 2>/dev/null
            done
        echo '--- realmd base schema ---'
        mariadb --skip-ssl -hdb -umangos -pmangos classicrealmd \
            < /mangos/sql/base/realmd.sql
        echo '--- realmd updates ---'
        find /mangos/sql/updates/realmd -name '*.sql' | sort | \
            while read f; do
                mariadb --skip-ssl -hdb -umangos -pmangos classicrealmd \
                    < \$f 2>/dev/null
            done
        echo '--- logs base schema ---'
        mariadb --skip-ssl -hdb -umangos -pmangos classiclogs \
            < /mangos/sql/base/logs.sql
        echo '--- logs updates ---'
        find /mangos/sql/updates/logs -name '*.sql' | sort | \
            while read f; do
                mariadb --skip-ssl -hdb -umangos -pmangos classiclogs \
                    < \$f 2>/dev/null
            done
        echo 'All done!'
    "

# TBC: alle "classic" durch "tbc" ersetzen, cmangos-classic durch cmangos-tbc,
#       cmangos-classic_mangos-net durch cmangos-tbc_mangos-net

Hinweis: 2>/dev/null unterdrückt harmlose "Table already exists" Fehler.
         Die Updates sind idempotent — bereits vorhandene Strukturen werden
         einfach uebersprungen.

--- Random Bots ---
Wandern automatisch durch die Welt wenn RandomBotAutologin = 1 gesetzt.
Im Log: "200 random bot accounts with XXXX characters available"

--- Eigene Bots ---
  .bot add BOTNAME       -> Bot hinzufuegen
  .bot remove BOTNAME    -> Bot entfernen
Addon: https://github.com/celguar/ikebotui

--- AI Chat ---
LLMEnabled = 2: AI Chat ist fuer alle Bots automatisch aktiv.
Einfach im Party-Chat schreiben.
LLMEnabled = 1: /p nc +ai chat  /  /p nc -ai chat

--- Charakter-Karten (optional) ---
nano config/llm_character_card.txt
Format: name::persoenlichkeit

  Sylvara::I am a mysterious night elf druid who speaks in riddles.
Volume in docker-compose.yml ergaenzen:
  - ./config/llm_character_card.txt:/opt/mangos/llm_character_card.txt

GM-Befehle: .ahbot reload / .ahbot clear / .ahbot items add all

================================================================================
  BEKANNTE FEHLER UND LOESUNGEN
================================================================================

FEHLER: AI Playerbot is Disabled. Unable to open configuration file
────────────────────────────────────────
Ursache: SYSCONFDIR = "../etc" relativ zur Binary = /opt/etc/ (nicht /opt/mangos/etc/)
         Mit strace bestaetigt: openat(AT_FDCWD, "../etc/aiplayerbot.conf", ...)
Loesung: Volume-Mount in docker-compose.yml:
           - ./config/aiplayerbot.conf:/opt/etc/aiplayerbot.conf
         Im Dockerfile:
           RUN mkdir -p /opt/etc && cp aiplayerbot.conf.dist /opt/etc/aiplayerbot.conf
           COPY --from=builder /opt/etc /opt/etc


FEHLER: character_db_version / realmd_db_version doesn't exist
────────────────────────────────────────
Ursache: InstallFullDB hat die Core-Updates nicht eingespielt (Option 3
         schlaegt bei neuem Bash mit "10#: invalid integer constant" fehl)
Loesung: Schritt 12 manuell ausfuehren — base schema + alle updates einspielen


FEHLER: "10#: invalid integer constant" beim InstallFullDB Option 3
────────────────────────────────────────
Ursache: Bekannter Bug in InstallFullDB.sh mit neueren Bash-Versionen
Loesung: Schritt 12 manuell ausfuehren (umgeht das Skript komplett)


FEHLER: "Your output directory seems to be polluted"
────────────────────────────────────────
Ursache: Alter Buildings/ oder vmaps/ Ordner vorhanden
Loesung:
  rm -rf wow-client/Buildings
  rm -rf wow-client/vmaps


FEHLER: VMap file './vmaps/000.vmtree' is missing or point to wrong version
────────────────────────────────────────
Ursache: vmaps von anderem Emulator (VMaNGOS etc.) — INKOMPATIBEL!
Loesung:
  rm -rf data/vmaps/*
  rm -rf wow-client/Buildings
  rm -rf wow-client/vmaps
  Dann Schritt 6 wiederholen (nur vmaps).


FEHLER: Extrahierte Dateien gehoeren root
────────────────────────────────────────
Ursache: Docker-Container laufen als root
Loesung: sudo chown -R $USER:$USER /programmieren/WoW/cmangos-classic/


FEHLER: AddAItem(): mAitems.find(...) == mAitems.end() / Server crasht
────────────────────────────────────────
Ursache: Korrupte Eintraege in der auction-Tabelle
Loesung:
  # Classic:
  docker exec cmangos-db mariadb -uroot -proot classiccharacters \
      -e "TRUNCATE TABLE auction;"
  # TBC:
  docker exec cmangos-db mariadb -uroot -proot tbccharacters \
      -e "TRUNCATE TABLE auction;"
  docker compose restart mangosd


FEHLER: Table 'ai_playerbot_random_bots' doesn't exist
────────────────────────────────────────
Ursache: Playerbots SQL-Tabellen nicht eingespielt
Loesung: Schritt 13 durchfuehren


FEHLER: TLS/SSL error: SSL is required
────────────────────────────────────────
Loesung: --skip-ssl Flag (in Schritten 12+13 bereits enthalten)


FEHLER: mariadb: unknown variable 'ssl-mode=DISABLED'
────────────────────────────────────────
Loesung: --skip-ssl statt --ssl-mode=DISABLED (MariaDB-Syntax, nicht MySQL)


FEHLER: Deprecated program name mysql / mysqldump
────────────────────────────────────────
Loesung: In InstallFullDB.config:
  MYSQL_PATH="/usr/bin/mariadb"
  MYSQL_DUMP_PATH="/usr/bin/mariadb-dump"


FEHLER: KoboldCPP OCI runtime error / executable not found
────────────────────────────────────────
Ursache: command-Block in docker-compose.yml fuer koboldcpp
Loesung: Nur environment/KCPP_ARGS — KEIN command-Block!


FEHLER: Bots antworten nicht mit KI
────────────────────────────────────────
  1. Endpunkt: http://koboldcpp:5001 (nicht localhost!)
  2. KoboldCPP bereit? docker compose logs koboldcpp -f
     Warten auf: "Please connect to custom endpoint at http://0.0.0.0:5001"
  3. AiPlayerbot.LLMEnabled = 2 in aiplayerbot.conf


FEHLER: "Can't get bot text loot! No bots texts loaded!"
────────────────────────────────────────
Ursache: Optionale World-Texttabellen fehlen (harmlos, Bots funktionieren)
Loesung (um Meldungen zu entfernen):
  # Classic:
  docker run --rm -it \
      --network cmangos-classic_mangos-net \
      -v /programmieren/WoW/cmangos-classic/playerbots:/playerbots \
      cmangos-classic \
      bash -c "
          find /playerbots/sql/world -maxdepth 1 -name '*.sql' | sort | \
              while read f; do
                  mariadb --skip-ssl -hdb -umangos -pmangos classicmangos \
                      < \$f 2>/dev/null
              done
      "
  docker compose restart mangosd


================================================================================
  NUETZLICHE BEFEHLE
================================================================================

Server stoppen/starten:
  docker compose down
  docker compose up -d

Einzeln neustarten:
  docker compose restart mangosd
  docker compose restart koboldcpp

Logs:
  docker compose logs mangosd -f
  docker compose logs koboldcpp -f

mangosd Konsole:
  docker attach cmangos-mangosd  (Detachen: Ctrl+P Ctrl+Q)

DB abfragen:
  docker exec cmangos-db mariadb -uroot -proot

Playerbots-Tabellen pruefen:
  docker exec cmangos-db mariadb -uroot -proot classiccharacters \
      -e "SHOW TABLES LIKE 'ai_playerbot%';"

Docker Speicher pruefen und bereinigen:
  docker system df
  docker system prune -f          # gestoppte Container + ungenutzte Images
  docker builder prune -f         # Build-Cache (sicher, gross!)
  docker system prune -f --volumes  # VORSICHT: auch ungenutzte Volumes!

DB-Backup:
  docker exec cmangos-db mariadb-dump -uroot -proot classicmangos \
      > classicmangos_backup.sql
  docker exec cmangos-db mariadb-dump -uroot -proot classiccharacters \
      > classiccharacters_backup.sql

Alles loeschen inkl. DB:
  docker compose down -v
  docker rmi cmangos-classic  # oder cmangos-tbc

Neu bauen:
  docker build --no-cache -t cmangos-classic .

Berechtigungen korrigieren:
  sudo chown -R $USER:$USER /programmieren/WoW/cmangos-classic/

KoboldCPP im Browser:
  http://localhost:5001
